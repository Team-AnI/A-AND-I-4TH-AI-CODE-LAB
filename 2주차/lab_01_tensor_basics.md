# Lab 01 · Tensor와 딥러닝 데이터 핸들링

> **한 줄 요약:** Tensor는 "**GPU에서 돌아가고, 스스로 미분되는 NumPy 배열**"이다.

## 🎯 이 실습에서 얻어야 할 것

- Tensor의 **shape, dtype, device** 세 가지 속성을 자유롭게 확인하고 조작할 수 있다.
- 인덱싱·슬라이싱·reshape로 **실제 데이터 전처리 상황**을 흉내 낼 수 있다.
- CPU와 GPU(또는 MPS) 사이로 Tensor를 이동시키고, **device 불일치 에러**가 왜 나는지 설명할 수 있다.

## 🗺️ 전체 지도 (Big Picture)

```
[ Tensor ]
   ├── 무엇이 들었나?   → shape, dtype
   ├── 어디에 있나?     → device (CPU / CUDA / MPS)
   └── 무엇을 할 수 있나? → 연산(+, @), 변형(view), 이동(.to)
```

딥러닝에서 데이터를 다루는 모든 순간은 결국 "**이 Tensor의 shape/dtype/device가 내가 원하는 대로 되어 있는가?**"를 계속 확인하는 과정입니다.

## 🧠 핵심 개념 요약

| 개념 | 한 줄 정의 | 왜 중요한가 |
|------|-----------|-------------|
| **Tensor** | N차원 숫자 배열 (NumPy ndarray의 확장판) | 딥러닝의 모든 데이터(입력, 가중치, 출력)가 Tensor |
| **shape** | 각 차원의 크기 튜플 | 층 간 차원 불일치 = 딥러닝 에러 1위 |
| **dtype** | 원소의 자료형 (`float32`, `int64` 등) | 모델 가중치는 대부분 `float32` |
| **device** | Tensor가 올라가 있는 하드웨어 | 서로 다른 device의 Tensor끼리는 연산 불가 |

### 🤔 자주 헷갈리는 포인트

1. **`view` vs `reshape`** — 메모리 연속성이 깨지면 `view`는 실패하지만 `reshape`은 (필요 시 복사해서) 성공함.
2. **`tensor.to(device)` 는 in-place가 아니다** — 꼭 `x = x.to(device)` 로 재할당해야 함.
3. **`torch.tensor(...)` vs `torch.Tensor(...)`** — 전자는 데이터를 복사해서 자동 dtype 추론, 후자는 생성자 (사용 비권장).

> "모르는 건 당연합니다. 다만 **AI에게 정답을 구걸하지 않고** 빠져나오는 법을 익히세요."

**Level 1 · 5분 이상 막혔다면 — 스스로 재확인**
- 에러 메시지의 **마지막 줄**과 텐서의 `shape` / `dtype` / `device` 를 소리 내어 다시 읽기
- PyTorch 공식 문서에서 문제의 함수 **한 줄 정의**만 확인 (튜토리얼 말고 레퍼런스)

**Level 2 · 10분 이상 막혔다면 — AI에게 "힌트만"**
```
나는 PyTorch Tensor 실습 중이고, <내가 지금 만든 텐서 shape/dtype/device + 원하는 목표>
상태에서 막혔어. 정답 코드는 주지 말고, 다음 한 줄을 짜기 위해 내가 스스로에게
던져야 할 질문 하나만 알려줘.
```

**Level 3 · 20분 이상 막혔다면 — 정답 받되 즉시 덮기**
- AI에게 정답 코드를 받되, **창을 닫고 자기 손으로 재작성** → 그 뒤에 비교
- 달랐던 줄을 한 줄씩 **말로 설명**해 보기. 설명 못 하면 그 줄은 아직 모른다는 뜻.
